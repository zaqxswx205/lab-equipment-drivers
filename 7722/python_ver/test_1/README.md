# IT-M7722 电源控制程序

Python/Tkinter 界面，默认接口 `serial / COM6 / 9600`，通过原 USB 线访问设备的虚拟串口。启动程序不会自动连接或开启输出。默认电压5V、频率50Hz，保护上限300V/6A/600W。

## 运行与离线测试

```powershell
C:\ProgramData\anaconda3\python.exe itech7722_driver.py
C:\ProgramData\anaconda3\python.exe -m unittest -v test_itech7722 test_regressions test_feedback test_recording_schema test_keypoints
```

其他带Tk的Python解释器需安装 `requirements.txt`。VISA连接另需pyvisa及相应后端。界面已移除USB-TMC专用选项、sim和仿真负载，内部仿真仅供离线测试。

## 连接和启动

“扫描串口”枚举全部品牌的COM口，列出名称和描述，不按VID/PID筛选。多个候选时由用户选择，扫描不打开端口或发送控制指令；连接后使用 `*IDN?` 确认型号。自检在后台执行，显示等待、应答或超时。现场已通过COM6读取IT-M7722型号，并验证NORM/PROT/MEAS子系统的部分查询；实际带载闭环仍需现场验证。

启动依次读取并记录旧错误、进入远程控制、关闭输出、准备日志、设置工作模式及硬件保护、写入目标设定，再开启输出。每条写入后检查错误，失败立即收尾。停止超时期间禁止重启和断开，关闭输出失败时保留报警。

默认指令依据 [IT-M7700编程手册](https://cdn.itechate.com/uploadfiles/%E7%94%A8%E6%88%B7%E6%89%8B%E5%86%8C/user%20manual/it-m7700/IT-M7700%20Programming%20Guide-EN.pdf)。`-113`为指令名不识别，`-350`为错误队列溢出，`-222`为参数超范围。IT-M7722保护设置超过300V/6A/600W时启动前拒绝下发。

## 定值与软件闭环

CV直接设置电压。CI/CP从0V开始，通过实测电流/有功功率调整电压，不把目标当作保护参数发送；达到目标后持续跟踪负载，超调优先降压。

闭环电压上限默认5V，升压步长默认0.2V。50Ω负载达到0.5A约需25V，需用户确认后明确调高闭环上限；程序不会自动放宽上限。闭环目标需不高于对应保护限值95%，调节也为保护预留余量。默认60秒无法达到目标、触及边界3秒、回读持续严重偏离3秒时停止。

现场低压回读可能存在偏置：0V附近仍有约1.7mA，0.1V设定可能回读约0.7V。因此低压区先使用不超过0.1V的小步试探，随后使用比例估算；跟随诊断允许偏差取 `readback_tolerance_v`（默认1V）和设定值3%的较大值。此容差不改变任何保护限值。

软件无法保证负载突变或采样间隙中不存在瞬态越限，必须配合设备硬件保护。过限、无效电压/电流/功率、反向回馈或通信失败时停止并尝试关输出。当前序列仅支持CV，CI/CP用于定值模式。ACDC单电压设定使用交流分量并清零直流偏置。

## 序列格式

新序列不再需要 `record` 列，格式为：

```csv
duration,control,value,frequency
3,CV,1,50
3,CV,3,50
3,CV,5,50
2,CV,0,50
```

`duration`为秒，必须为正数；`control`为CV；`value`为电压；频率省略或填0时沿用全局值。已移除 `record` 和 `desc` 列，旧文件中的这两列可兼容读取但不生效。序列步骤、状态提示和数据日志不再输出desc。示例使用带BOM的UTF-8，仍兼容读取旧的中文ANSI文件。

## 全软件统一记录

定值、闭环、序列和关键点日志固定记录：

| 列 | 含义 |
| --- | --- |
| voltage | 电压V |
| current | 电流A |
| power | 有功功率W |
| power_factor | 功率因子，无量纲 |

功率因子通过 `MEAS:POW:PFAC?` 查询，不用电压电流乘积冒充。无有效应答时留空，界面显示 `--` 并注明无有效回读，不伪造为0或1。频率仍用于设备设定与内部测量，不占用上述四项记录列。界面取消参数勾选和关键点参数筛选，仅保留“启用记录”开关。

默认记录间隔1秒，界面以秒输入，配置为 `[Recording] interval_ms = 1000`。闭环控制周期200ms独立于写文件周期，实际周期受通信耗时限制。实时曲线仅显示功率，使用每次回读更新。

相对序列和日志路径按配置文件目录解析。现有日志表头缺少功率因子或不符合新格式时，首次开始记录先复制到 `原文件名.backup_时间戳`，备份成功后才建立新表头；旧数据不会混入新列。程序不会补造历史功率因子。关键电压点仍按边沿触发，但命中后同样记录全部四项。

config.ini为当前配置，sample_config.ini为同格式样例。配置保存和示例修改不会直接改变正在运行的旧窗口，请重启以加载代码更新。

### 达标判定与结果文件精简

`data_log.csv` 当前列为 `time,step,voltage,current,power,power_factor,mode,setting`，不再输出elapsed_s、status或desc。界面和控制内部仍保留计时与状态，用于曲线、报警和调节。旧日志在新版首次启动记录时按旧表头备份，备份中的历史数据保留原样。

CI/CP采用单边保持范围：`目标值 ≤ 实测值 ≤ 目标值+max(上侧容差,目标值×5%)`。低于设定值时，无论差距是否小于容差，都不判定达标；例如3W目标下2.9W、2.99W均继续调节。调节中心在目标上方半个容差，接近目标时保留不超过升压步长的最小正向探测，避免渐近停在目标下方。过度超调时向该中心降压，不再刻意降至目标以下。

爬升过程仍正常记录低于目标的测量值，这些不是达标结果；负载变化后跌破目标会恢复调节。如果在电压/保护边界内无法达到目标，则报错并关闭输出，不放宽限值或伪造测量数据。

### 达标保持与自动保存

达标后保持电压并持续测量；例如2W目标下2.013W、2.039W、2.008W等小幅上侧变化不会触发调压。跌破目标立即恢复升压，仍不把低于设定值判为达标。上侧明显偏离保持区间时确认持续1秒后再修正；超过目标20%的明显超调以及接近保护边界时优先修正，不等待普通波动确认。保护检查始终执行。

原“保存配置”用于将界面参数写入文件，“加载配置”用于恢复文件中的参数。现已移除两个手动按钮和单独选择配置文件的流程；启动运行前及正常关闭窗口时自动保存到config.ini，下次启动读取。保存使用临时文件替换，避免写入中断损坏原配置。自动恢复连接、保护、记录及闭环等偏好，但每次打开程序仍重置为CV/5V/定值模式，不沿用上一次高功率或高电流目标；不会自动连接和开启输出。

### 关键设定电压采集

“数据记录”区域内的关键点规则仅显示“关键设定电压”，不再显示记录参数、命中区域或容差。按实际下发的电压设定相等触发（以SCPI六位小数精度比较），与回读电压是否等于该值无关。例如设定5V、回读5.05V，会记录关键设定5V及四项当时实测数据。

关键点检查在每一次采样上执行，与普通CSV的记录周期独立；连续保持同一设定只记录一次，切换到其他设定再返回会重新记录。运行中增删规则通过线程队列同步，下一次采样生效，无需重启。闭环升压变步长可能跨过关键设定值，因此在不提高控制电压和保护上限的前提下，优先落在途经的关键设定值上采样；降压保护不受关键点阻碍。修复累计浮点截断造成1V等整数设定被跳过的问题。

关键点日志固定列为“关键点设定电压(V)、time、voltage、current、power、power_factor”；旧表头文件首次记录时先备份。全局“启用记录”仍控制是否写文件。串口扫描已与品牌检测解耦，底层电源SCPI协议仍按当前设备映射配置。

界面已移除 SCPI 指令映射、SCPI 调试台和使用说明页。关键设定电压规则集中在“数据记录”区域，底层设备通信与保护检查继续正常工作。
