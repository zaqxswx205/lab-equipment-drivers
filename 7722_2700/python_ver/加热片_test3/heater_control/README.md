# 7722制冷机交流驱动 + 2700 Pt100采集

运行 `app.py` 或双击 `start.bat`。所有脚本均在本目录独立实现，可以单独复制此文件夹；需要带Tk的Python及 `requirements.txt` 中的pyserial。界面不提供模拟运行。

主界面分为同级的“设备与实验设置”和“实时曲线”两个标签页。设置页保留设备参数、驱动方案、测温通道表格，交流驱动的启动、阶段、停止及保护状态显示在“7722 交流驱动”面板内，2700的连接、采集、停止及通道异常显示在“2700 采集与保护”面板内；保存配置与启动按钮所在行不再显示混合运行状态。曲线页提供大面积温度、阻值、功率图表和通道选择，并同步显示运行状态、电源读数，提供独立的“停止采集”和“停止驱动”按钮。切换页面不影响采集、文件记录和曲线历史积累，回到曲线页自动重绘。

“设备设置”外框中并列显示“7722 交流驱动”和“2700 采集与保护”，串口设置分别放在对应设备框内，支持串口扫描及下拉选择。7722固定交流模式，主界面设置频率、最大电压、最大电流、最大功率。2700设置参考温度通道与采集参数；温度保护范围在测温通道中逐路设置，所有已添加通道都采集并按自身上下限参与越限检查。

## 操作

1. 选择两台设备各自串口，“高级设置…”中设置波特率、2700流控及通信超时。
2. 按真实制冷机设置7722频率与电压/电流/功率上限。随附3V、0.2W等仅为文件格式示例，不是制冷机推荐运行参数。
3. 在“测温通道”中为Slot 1（1xx）和Slot 2（2xx）分别选择模块7700/7702及两线/四线制。例如Slot 1为7700四线、Slot 2为7702两线；同一槽内共用设置，两槽可不同。再添加各路通道及两线引线电阻补偿。2700实体开关切至REAR。参考通道例如102触发阶段、101同步记录，也可跨槽使用201等参考通道。
4. 在“驱动方案配置文件”中选择方案，可以“编辑方案…”并刷新预览。“保存配置”写入主配置 `config.ini`，新一轮首次启动前也会保存。驱动运行时不可编辑或切换方案，外部文件改动也不会改变已启动的方案；仅采集时可切换方案供下一次驱动使用。
5. “开始采集”和“开始驱动”分别操作：只采集时仅连接2700，不连接7722，也不要求驱动方案文件存在；单独驱动时仅连接7722，执行已选择的时间方案。温度方案需要先启动采集，第一轮有效温度返回后才允许输出。
6. 可以先开始采集再加入驱动，或先运行时间驱动再加入采集。两个按钮分别变为“停止采集”“停止驱动”，停止一项后等待对应设备清理完成再恢复开始。停止驱动可以继续采集；停止采集时，时间驱动可以继续，温度驱动会同步停止。单独运行时间方案时没有温度保护，电源电压/电流/功率保护仍生效。
7. 运行中设备参数使用首次启动时的快照，不从正在编辑的界面取值。驱动停止后可以在继续采集的同时选择、编辑驱动方案，再次开始驱动会从新方案第一个阶段重新判断，时间方案的分钟数重新从0起算。两项都停止后再启动，会清空曲线并建立新记录文件。
8. 关闭窗口会停止采集与驱动并等待清理。真实电源通过 `OUTP:STAT?` 核对关断，未确认时保留报警并禁止再次驱动；仍可只采集观察温度。电阻无效、超出Pt100换算范围或温度越限时继续采集与记录；正在运行的驱动会关闭输出并停止，需要手动重新启动。通信故障、电源测量越限等异常仍停止整个运行并尝试关输出。

## 方案格式

主配置 `config.ini` 中，`profile_file` 为方案路径，`reference_channel` 为参考温度通道。相对方案路径按本程序目录解析，迁移时将方案文件一并复制。

按时间执行 `drive_time.ini`：`at` 为本轮驱动初始化完成后的分钟数，必须按文件顺序严格递增。每次重新开始驱动都会从0计时，不依赖采集是否先启动。

```ini
[Drive]
strategy = time

[Step 1]
at = 0
mode = voltage
value = 0

[Step 2]
at = 1
mode = voltage
value = 3

[Step 3]
at = 2
mode = power
value = 0.2

[Step 4]
at = 5
mode = voltage
value = 0
```

含义：第0分钟关闭输出，第1分钟起3V交流驱动，第2分钟起反馈调节至0.2W，第5分钟关闭输出并继续采集。

按降温阈值执行 `drive_temperature.ini`：改为 `strategy = temperature`，设置 `temperature_unit = K`，各阶段 `at` 为K，必须严格递减，例如303.15、283.15、273.15。参考温度≤303.15 K执行阶段1，≤283.15 K执行阶段2，≤273.15 K执行阶段3；触发后温度回升也不回退。

第一阈值前关闭输出等待。初始温度已低于多个阈值时直接执行最后一个已达到的阶段，不逐一开启被跨过的阶段。停止后重新启动会从头判断。

两种方案都不插值，最后阶段一直保持，除非设为0或用户停止。`value=0` 在两种模式中都关闭输出并继续采集。希望结束驱动时添加最后一个0设定阶段；采集仍需手动停止。每轮采集后按最新时间/温度判断，无法保证在指定分钟的瞬间切换，跨过多个阶段时只执行最新已达到的阶段。

## 电压与功率

- `mode = voltage`：`value`单位V，直接设置7722交流电压，不执行目标温度PI调节。
- `mode = power`：`value`单位W，根据实测有功功率反馈升降电压。底层仍执行CV，不把功率保护指令当成恒功率设定。
- 电压设定不得超过最大电压；功率目标不得高于功率保护的95%。电源保护、温度和通信检查始终执行，失败不会自动放宽限值。
- “功率调节设置…”控制最大升压速率、相对容差和持续未达标停机时间；保持容差取 `max(0.02W, 目标功率×相对容差)`。目标改变重新计时；连续不达标到超时则停机。

功率反馈周期受2700逐通道采集、稳定时间和串口耗时限制，不保证瞬态恒功率或无超调。参数和允许的电压/功率变化应按实际制冷机确定。

## Pt100、通道与记录

2700通过 `RES` / `FRES` 测电阻，用Callendar–Van Dusen方程换算标准Pt100（100Ω@0℃、α=0.00385，-200至850℃），系数见[Analog Devices资料](https://www.analog.com/en/resources/technical-articles/highaccuracy-temperature-measurements.html)。不使用内置TEMP功能。两线可减去总引线电阻补偿；四线补偿须为0；不支持三线补偿。

| 模块 | 每槽两线通道 | 四线源通道 | 四线感测配对 |
| --- | --- | --- | --- |
| 7700 | 01–20 | 01–10 | 源通道+10 |
| 7702 | 01–40 | 01–20 | 源通道+20 |

槽位1为1xx，槽位2为2xx。启动时通过 `*OPT?` 分别核对有采集通道的槽位型号；未添加通道的槽位可以为空。软件共用2700主机表头逐通道采样：先打开所有通道，再按所在槽位切换 `RES` / `FRES`，最后接通当前通道测量，不同时进行两种功能的转换。

四线配对感测通道不能独立添加，可选通道范围随各槽模块和接线制联动。切换某槽至四线制，只清零该槽的两线补偿，不影响另一槽；选择四线通道时补偿输入禁用，表格显示按模块计算的感测配对通道。已有不兼容通道会提示删除，并在保存、运行时拒绝无效配置。运行期间禁止更改槽位设置。

配置文件 `[Settings]` 中，`slot1_module` / `slot1_wires` 和 `slot2_module` / `slot2_wires` 为两槽的模块及接线制；`[Channel 101]` 等各通道段仅保留 `lead_ohm`。旧全局设置迁移到两槽；旧逐通道设置按槽归并，同槽不一致或与显式配置冲突时拒绝迁移。原配置保存在 `config.before_slot_measurement.ini`。

官方依据：[2700用户手册](https://download.tek.com/manual/2700-900-01K_Feb_2016.pdf) 第1-6、1-8、2-31页说明双槽、模块功能与型号查询，第7-31页说明四线配对；[7700/7702模块指南](https://download.tek.com/manual/PA-695%28D-Oct2006%29%287700%29.pdf) 第2、6页说明两种模块的两线/四线功能及配对。硬件允许按通道配置测量功能；本软件根据当前使用要求，将接线制按槽统一管理。

每轮优先采参考通道，再采其他通道，确认有效后执行阶段。`data/` 下独立创建CSV和通信日志，不覆盖旧文件。CSV在同一表中先列2700数据（时间、通道、接线制、电阻、温度K），再列7722方案、阶段、驱动方式、目标、设定电压、输出状态和实测电压/电流/有功功率/功率因子，每行写入后flush。时间格式为 `2026-11-02 09:52:01`，不含T和毫秒；已删除 `elapsed_min`、`reference_channel`、`drive_elapsed_min` 三列。CSV不再包含 `measurement_status` 列，异常原因保留在界面和通信日志中；无效阻值保留原始返回值，无法换算的温度留空，不影响其他通道及后续轮次。异常值不参与驱动判断，NaN和仪器超量程占位值不绘入阻值曲线。各路为顺序采样，电源测量属于该轮调节后的数据，并非严格同步。通信日志记录配置、方案快照及SCPI收发。

每次成功启动2700采集都新建CSV，文件名为日期加开始采集时间，例如 `20261102_095201.csv`；同一秒重复启动时追加 `_02` 等序号，避免覆盖。连续跨天时新建当天文件。只运行7722驱动时也创建CSV保存电源数据，随后加入2700采集则新建采集文件。只采集时电源字段留空，只驱动时测温字段留空。停止驱动后重新驱动不会切换当前采集文件；停止采集后再次启动会新建文件，即使驱动一直运行。曲线仍沿用本次运行时间轴，文件分段不会清空曲线。历史CSV保留原格式。

测温通道表格同时显示实时温度（K）与实时阻值（Ω）。阻值是2700原始实测电阻，与CSV一致，未扣除引线补偿；温度按该通道补偿后的电阻换算。下方“各通道温度”和“各通道阻值”选项卡显示各路曲线，以颜色与线型、通道号图例区分；“显示通道”可选全部或单路。每路保留最近600点，横轴使用该通道实际采样时刻相对于本轮运行开始的秒数，切换选项卡不丢失历史。新一轮启动清空表格旧读数与曲线。

“7722 有功功率”选项卡显示电源实测有功功率（W），横轴为该轮记录的运行秒数，保留最近600点。功率来自电源测量，不使用设定功率或电压电流乘积代替。功率曲线独立于测温通道选择，该选项卡下暂时禁用通道选择框；新一轮启动清空功率历史。

采样时间只需设置两项：“采样稳定时间” `settle` 为每次切换通道后、读取前的等待时间；“通道采样间隔” `interval` 为相邻两次通道采样开始之间的期望间隔，包括最后一个通道到下一轮第一个通道。每次采样包括通道切换、稳定等待和测量通信，提前完成则等待剩余间隔；耗时超过间隔则立即采下一路，不再额外等待。不会在整轮结束后再等待一次。单个通道再次被采集的间隔约为通道数乘以设置值，实际可能因通信与驱动耗时延长。界面不再显示NPLC，使用内部默认值1；已取消温度有效时限及其过期停止逻辑，旧配置中的 `max_sample_age` 自动忽略。温度驱动始终使用当前轮参考温度。串口调用仍需等待通信超时；停止也需等待当前调用返回。软件检查不能代替独立硬件保护。

## 文件与验证

`app.py` 只保留入口：解析参数并在 `--smoke` 时构建界面后自动关闭，其余为 `App().mainloop()`。界面代码在 `ui/`，按界面区域拆分：`ui/app.py`（窗口状态、主循环、事件调度）、`ui/layout.py`（设置页与曲线页布局）、`ui/form.py`（配置字段与采集设置）、`ui/actions.py`（启停、保存、运行按钮状态）、`ui/events.py`（工作线程事件分发）、`ui/dialogs.py`（功率调节、连接设置、方案预览/编辑）、`ui/plots.py`（曲线绘制）、`ui/ports.py`（串口扫描），通过 mixin 组合为 `App`。

后端按职责拆分，一个文件只负责一类功能：`model/` 放数据模型与规则（`pt100` 换算、`channels` 通道与槽位、`config` 字段、`config_validate` 校验、`config_io` 读写与旧格式迁移、`measurements` 越限检查）；`instruments/` 放仪器通信（`transport7722` 串口与模拟传输、`meter2700` 采集、`meter2700_sim` 离线采集）；`profile/` 放驱动方案（`model` 阶段与文件解析、`sequencer` 阶段推进、`controller` 功率反馈调压）；`session/` 放运行流程（`controls` 启停信号、`devices` 设备打开/关断/清理、`acquisition` 单轮采集、`drive` 单轮驱动、`heater` 加热轮次与温度触发、`records` 通信日志、`runner` 主循环编排）。

`core.py`、`runtime.py`、`drive_profile.py`、`power7722.py` 保留为兼容转发的薄封装（`power7722.py` 仍包含 7722 指令实现），对外导入路径、类与方法签名、事件与日志文案均与旧版一致，原有测试无需改动。所有模块均不超过 250 行。旧主配置备份为 `config.before_stage_drive.ini`，主配置已去除目标温度PI参数。

```powershell
C:\ProgramData\anaconda3\python.exe -m unittest discover -v
C:\ProgramData\anaconda3\python.exe app.py --smoke
```

少数依赖时间边界的用例（阶段切换、零输出阶段联动停止加热）在机器负载高时可能偶发失败，重构前后表现相同；完整结果以 `unittest discover` 一次全绿为准，可重跑确认。

离线测试覆盖分钟边界、降温阶段不回退、电压/功率混合阶段、零设定关输出、功率跟踪及超时、非法方案禁止打开串口、Pt100换算、通道冲突、通信故障与收尾。模拟器只供测试使用，无界面入口。本版尚未连接真实制冷机及2700验证。

每路温度保护：选中通道后填写“保护下限(K)”与“保护上限(K)”，点击“添加/更新”，再保存配置。允许范围为下限 ≤ 温度 < 上限，阈值须满足 73.15 K ≤ 下限 < 上限 ≤ 1123.15 K。任一路越限均停止7722驱动并关闭输出，2700继续采集记录，不自动恢复驱动。温度方案的降温阈值须严格位于参考通道保护范围内。上下限保存到各 `[Channel xxx]` 节的 `min_temperature`、`max_temperature`；旧配置的全局上下限自动迁移至尚未单独设置的通道。

温度显示、曲线、保护阈值输入和新CSV统一使用K（temperature_K），换算为 K = 摄氏温度 + 273.15。配置与温度方案使用 temperature_unit=K 标记单位；无标记旧文件按C读取，保存配置或编辑温度方案时转换为K，保持实际阈值不变。历史CSV不改动，内部Pt100公式仍用摄氏度计算。

7722关断确认：停止驱动、温度保护、零输出阶段及退出清理均发送OFF并等待状态回读，暂时返回ON时重复关断与确认。持续未确认OFF时保留串口和非守护工作线程，持续报警及重试，禁止重新驱动；停止或关闭窗口不会打断关断重试。此时暂停2700采集以优先处理关断，请通过面板手动关闭电源。只有明确读回OFF后才释放串口并完成停止/退出；不会自动恢复输出。通信日志记录每次回读和重试。

2700失联保护：独立非守护线程监督每次读取及初始化的进度。通信超时、返回错误、设备错误会触发保护；调用卡住时，读取限时为稳定时间 + max(5秒, 3×通信超时)，初始化限时为 max(15秒, 5×通信超时)，采样间隔等待计入允许等待时间，无需额外设置。故障时旧读数标记采集失效，锁止所有开启/调压指令，独立线程发送OFF并确认，主采集调用未返回也不影响该关断任务；未确认OFF持续重试。恢复通信后不自动恢复输出，须结束当前故障运行并重新启动。关断确认与采集线程清理完成之前保留线程和串口。电脑死机、进程被强制终止、断电或电源通信断开无法由软件保证关断，需要独立温度/失联硬件联锁。


## 第二台7722：负载加热

在设备设置中，与“7722 交流驱动”“2700 采集与保护”并列的“7722 加热负载”面板内，选择电源实际串口、控制方式、目标值及电压/电流/功率保护，波特率在“高级设置…”内设置。填写后点击“保存配置”，再点击操作按钮行的“开始加热”。加热、交流驱动和采集独立启停。参数需依据实际加热片额定值填写。

点击“开始加热”后只连接加热面板指定的7722，输出固定为DC，不要求另一台7722或驱动方案文件存在，但会自动启动2700采集；必须取得一轮有效且未越限的温度数据后才允许加热输出。选择“恒定电压”时按用户设定的电压直接输出；选择“恒定功率”时按用户设定的功率自动反馈调压，非当前模式的目标输入禁用。直流输出不使用驱动电源的交流频率。以下反馈算法仅用于恒定功率模式：程序读取加热电源自身的有功功率，以电阻负载关系 V新 = V旧 × sqrt(P目标/P实测) 估计调压，并限制升压速度；启动零功率时逐步升压。每轮读数后重新调整，达到 max(0.02W, 目标×相对容差) 后保持，偏离后继续调节。界面显示目标、实测、电压、电流和达标状态。目标为0时保持输出关闭。升压速率、容差及持续未达标超时共用“功率调节设置…”。尝试次数取决于负载、采集周期和升压限制，不保证固定次数收敛；超时会停止驱动并关断两台电源。

“停止加热”只停止加热，“停止驱动”只停止交流驱动；温度越限、2700通信故障和窗口退出关闭所有正在运行的电源，均需OFF回读确认才释放串口。仅开始采集不会打开加热电源。运行中不修改加热设定，停止后修改并重新启动。加热反馈受2700采集耗时影响，与原驱动每轮各调节一次；加热必须伴随2700采集；单独交流时间驱动仍可不启动采集。加热读数写入同轮通信日志中的 HEATER 行，现有CSV列仍记录制冷机驱动读数。

新增离线测试：`python -m unittest test_heater -v`。尚未连接第二台真实7722及加热片验证，应先使用符合负载额定值的低功率设定核验。

界面顶部同一行依次放置7722交流驱动、7722加热负载、2700采集与保护和驱动方案配置文件。加热控制方式、设定电压和目标功率分别保存为 heater_control（voltage/power）、heater_voltage、heater_power。旧配置缺少新字段时默认使用恒定功率，输出改为DC。

两台7722的波特率统一在“高级设置…”打开的“连接高级设置”中修改，分别标注“7722 交流驱动（AC）波特率”和“7722 加热负载（DC）波特率”。各设备的串口号仍在对应主面板选择。

仅用原交流驱动的7722测试加热：将其实际串口填入“7722 加热负载”，在高级设置设置该设备波特率，选择DC恒定电压或恒定功率及目标值，然后只点“开始加热”。两个面板可以配置同一个串口，但程序禁止同时启动使用同一串口的设备。开始/停止按钮会显示启动中、运行读数或连接错误；更改程序后请关闭旧窗口，重新运行 app.py 或 start.bat。

“开始加热”与“开始驱动”“开始采集”位于同一操作按钮行。已撤回电流零点容差及归零处理。加热使用DC电流回读，显示与日志保留原始正负号，按 abs(current) 与最大电流比较；任一方向超过电流上限、NaN/Inf均停机。AC有效值仍要求非负。功率调节首次启动不采用关输出时残留的功率作为反馈，首次升压步长按一个反馈周期和配置升压速率计算，后续按实际周期调节。

“开始加热”旁有“加热联动保护”勾选开关，每次启动软件默认开启。开启时，必须等待7722交流驱动实际开启输出后才能点击开始加热，连接中、停止中、零输出阶段及未运行时均禁止启动加热。驱动停止或进入零输出阶段时停止加热，不自动恢复；停止加热按钮始终可用。关闭联动保护后可不启动交流驱动，但加热仍会自动启动2700采集。加热运行期间重新开启联动保护，如交流驱动未输出则立即请求停止加热。

用户关闭“加热联动保护”后，下次成功点击“开始驱动”会自动重新勾选并启用联动保护。驱动连接期间开始加热仍禁用，交流输出开启后自动恢复可点击；不会自动启动加热。

加热面板的设定电压与最大电压合并为一个输入框：恒定功率时标为“保护电压(V)”，仅限制反馈调压上限；恒定电压时标为“设定电压(V)”，同时用作输出设定与电压保护上限。切换模式时保留输入数值，恒定电压下目标功率输入禁用。配置仍保留旧 heater_voltage 字段以兼容历史文件，界面保存恒定电压模式时将其与 heater_max_voltage 同步。

## 温度控制加热

2700面板提供“温度控制加热”（默认关闭）、“加热触发温度(K)”及“到温度开启/到温度关闭”。不再选择升至或降至，按降温实验流程，参考通道温度≤阈值时执行动作，初始温度已满足条件也执行。阈值须严格位于参考通道保护范围内；本轮全部采集通道须有效且无温度越限。

选择“到温度开启”：自动请求启动加热，采用加热面板中的DC电压/功率设定。加热联动保护开启时必须交流驱动实际开启输出，否则等待后续采样重新判断；联动关闭时可以只启动2700等待温度触发。

选择“到温度关闭”：用户可先手动开启加热；参考温度达到阈值后，自动停止加热并确认OFF，交流驱动和2700继续运行。关闭动作不受加热联动保护限制。

每轮会话只执行一次温度动作。到温度开启模式中，用户已经手动开启过加热后，本轮不再自动开启。手动停止或本轮出现无效/越限温度后不自动重启。全部设备停止后重新启动才重置自动触发状态。未采集时不使用历史温度执行动作。此功能不执行恒温控制。

配置使用 heater_trigger_action=on/off；旧 heater_trigger_direction 参数忽略。温度按 temperature_unit 保存，界面与新配置使用K。运行参数使用会话开始时的快照，修改后需停止本轮再重新启动；实际动作受通道采样与通信耗时影响。

加热启动、运行及关断确认期间，已运行的2700采集不能单独停止：设置页与曲线页的停止采集按钮均禁用，后端也拦截停止请求。先停止加热并确认OFF后恢复停止采集功能。温度/通信故障和退出程序仍按保护流程先关闭电源，再清理采集。如果采集尚未运行，“开始加热”会自动启动2700。2700初始化、测温或通信失败时不允许加热输出；加热关闭后采集继续，用户可再手动停止采集。关闭加热联动保护也不能绕过采集保护。
